# Arch Linux: изменить и обновить одной командой

Этот сценарий рассчитан на **Arch Linux x86_64** и уже настроенный P30 владельца. Root-репозиторий не нужен. Проектор и компьютер должны быть в одной сети, сетевой ADB — доступен.

## Один раз перед началом

Распакуй исходники `focal-launcher`. Отдельный **PRIVATE update kit** распакуй прямо в корень этой папки: появятся игнорируемые `local/device.json` и `local/signing/rice-development.jks`. Оба файла приватные, на GitHub их не добавляют. Они не входят в публичные архивы с исходниками.

В `local/device.json` хранится привязка к этому проектору. Если изменился IP, обнови только `adb_serial`. Проверенный `ro.serialno` и платформу нельзя заменять значениями случайного подключённого устройства.

## Обновить проектор

Из корня репозитория:

```sh
./focal update
```

Команда:

1. Проверяет наличие приватной конфигурации и оригинального ключа.
2. При необходимости устанавливает официальные Arch-пакеты `git`, `python`, `nodejs`, `jdk21-openjdk`, `android-tools`. Pacman/sudo могут попросить обычное подтверждение или пароль в терминале. Полное обновление системы автоматически не запускается.
3. Находит JDK 21, не меняя системную Java по умолчанию, и проверяет сертификат ключа.
4. Выполняет офлайн-проверки исходников и веб-пульта.
5. Загружает закреплённые Linux Build Tools 35.0.0 и Platform 30 напрямую у Google, проверяет SHA-256 и собирает подписанный APK.
6. Подключается только к заданному ADB-адресу, проверяет APK, идентичность проектора, штатные бинарники и уже работающую factory-службу. Затем выполняет обычное `adb install -r`.

Темы, избранное и сопряжение телефонов сохраняются. Прошивка, перезагрузка, root-установка, удаление приложения, очистка данных и смена HOME не выполняются. После обновления веб-пульта перезагрузи его страницу на телефоне. Успешное обновление APK не означает исправление известной проблемы vendor-автозапуска после питания.

Если возникла ошибка, установка не продолжается через обход проверок. При несовпадении подписи нельзя удалять приложение: нужен правильный оригинальный ключ.

## Обычный цикл разработки

Попроси агента изменить нужную функцию. Он читает AGENTS.md, меняет исходники, повышает `versionCode` и `versionName` для обновления приложения, затем выполняет:

```sh
./focal check       # Только офлайн-проверки
./focal build       # Подготовка инструментов и сборка, без устройства
./focal update      # Проверки, сборка и обновление проектора
```

Для одного шага после изменений достаточно `./focal update`: он включает проверку и сборку. Commit/push на GitHub — отдельные действия с исходниками; обновление проектора не публикует код автоматически.

Без оригинального ключа можно собрать APK **только для отдельного тестового устройства**: `./focal build --test-key`. Подпись будет другой, а установка такого APK через наш обновлятор на проектор владельца блокируется. Эта опция не поддерживается командой update.

## Дополнительные параметры

`--no-system-install` запрещает установку системных пакетов. `--sdk`, `--work`, `--java-home`, `--keystore`, `--adb`, `--device-config` задают свои пути. Например `./focal update --serial projector.local:5555` меняет адрес подключения без изменения ожидаемой физической идентичности. Все параметры показаны в `./focal --help`.

Для обычного рабочего места достаточно распакованного приватного комплекта и `./focal update`. Запускать команду от root не нужно: sudo используется только для отсутствующих пакетов, сборка и ADB работают от обычного пользователя.

Linux ARM64 не поддерживается закреплёнными Google host-бинарниками; скрипт явно отказывается использовать вместо них macOS-файлы. macOS поддерживается своим набором SDK; автоматическая установка системных пакетов реализована только для Arch.

Официальные источники: [JDK 21 в Arch](https://archlinux.org/packages/extra/x86_64/jdk21-openjdk/), [ADB в Arch](https://archlinux.org/packages/extra/x86_64/android-tools/), [Android Build Tools](https://developer.android.com/tools/releases/build-tools). Контрольные суммы и проверка распаковки находятся в `scripts/toolchain.py`.
