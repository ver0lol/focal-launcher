# Разработка и сборка

## Публикация исходников

Для первого размещения на GitHub не нужны проектор, ADB, Android SDK или ключ подписи. Начните с [OWNER_SETUP.md](../OWNER_SETUP.md) и [PUBLISHING.md](PUBLISHING.md). Команды build/install относятся к последующей разработке.

## Офлайн-проверки

Нужны Git, Python 3.9+, Make и Node 24+:

```sh
make check
```

Проверяются Python/JSON/XML, внутренние ссылки, приватные файлы, контрольные суммы upstream и отказ device-guard без собственной конфигурации. Затем запускаются девять контрактов JavaScript веб-пульта: касание, очередь, устаревшие повторы, фокус клавиатуры, текст, ограничения алфавита, сохранение черновика и отсутствие автоматического повтора. ADB, интернет и SDK не используются.

Без Node можно сначала выполнить `make check-python`; полную проверку веб-клиента выполните после установки Node. Путь к нему можно передать как `make check NODE=/path/to/node`.

## Сборка Android

Нужны JDK 21, Python 3.9+ и Android SDK Platform 30 / Build Tools 35.0.0. `make bootstrap` скачивает закреплённые архивы Google для Linux или macOS и собирает приложение. Если SDK уже есть, используйте `make build`. По умолчанию инструменты и промежуточные файлы остаются в игнорируемом `work/`, результат — в `dist/`.

Автоматический путь для Arch x86_64 — `./focal build` или `./focal update`. Подробности: [ARCH-LINUX.md](ARCH-LINUX.md). SDK выбирается для текущей ОС и проверяется по SHA-256. Поддерживаются стандартные каталоги SDK и прежний формат распакованных архивов.

Пути на своём компьютере можно задать в `local/build.mk`:

```make
SDK_DIR := /path/to/android-sdk
BUILD_DIR := /path/to/private/launcher-build
JAVA_HOME := /path/to/jdk-21
ADB := /path/to/adb
NODE := /path/to/node
SFA_APK := /path/to/SFA-1.14.4-armeabi-v7a.apk
```

Сборщик также принимает `--sdk`, `--work`, `--java-home`, `--output`. Новый ключ создаётся только при явном `--test-key`, для отдельного тестового устройства. По умолчанию нужен оригинальный ключ из `local/signing/rice-development.jks` (или прежнего work-каталога); его сертификат проверяется до сборки. **Для обновления уже установленного лаунчера нужен его оригинальный ключ** `rice-development.jks`, переданный отдельно. Не заменяйте ключ и не удаляйте приложение при ошибке подписи: это потеряет совместимость и данные. Приватные ключи не публикуются.

Сертификат установленной пары launcher/VPN: SHA-256 `068bcd61ba49ffc0d8c5050fd45cc9aed39c22ca830bedab0f35b473c392a9e5`. Это публичный отпечаток, не ключ. `make build` ничего не устанавливает и не меняет проектор.

## Локальная конфигурация

Она нужна только при работе с устройством или сборке своего VPN companion:

```sh
mkdir -p local
cp config/device.example.json local/device.json
cp config/vpn.example.json local/vpn.json
```

Укажите проверенные ADB-адрес и точный `ro.serialno` своего проектора. Остальные поля описывают поддерживаемую плату. Шаблон намеренно не проходит проверку; сетевой адрес не заменяет проверку физической идентичности.

В `local/vpn.json` задайте свой HTTPS `source_url` и совместимое имя профиля. Сам VPN JSON с доступами в репозиторий не добавляйте. Сборка `make vpn` использует официальный SFA 1.14.4 ARM32 с закреплённым SHA-256 и исходный ключ подписи. Сгенерированный `VpnBuildConfig.java` остаётся в игнорируемом work-каталоге. URL входит в приватный APK: такой APK также не коммитится. Источники и лицензии — [THIRD_PARTY.md](../THIRD_PARTY.md).

## Проверки с устройством

`launcher/qa/check_remote_http.py` — отдельная живая проверка HTTP с явным `--url`. Подключается по PIN, не отправляет действительные нажатия/текст. Выполняется только в задаче, где владелец разрешил доступ к нужному устройству.

`launcher/qa/verify_emulator.py` — исторический сценарий ранней версии Rice. Он жёстко ограничен отдельным `emulator-5580`, ranchu/API 30, очищает только тестовое приложение и пока не соответствует интерфейсу 0.5.3. Не считать его действующим регрессионным тестом и не запускать на физическом проекторе.

`singbox-integration/qa/build_probe.py` собирает временный диагностический APK без установки; пути SDK/JDK/ключа задаются аргументами. Он не нужен для обычной публикации или сборки лаунчера.

## Установка обновления

Только в отдельной авторизованной задаче на устройстве:

```sh
./focal update
```

Проверяются конфигурация, идентичность, firmware hashes, существующий factory daemon и APK checksum. До соединения проверяются хеш и сертификат APK, затем выполняется `adb install -r`. Reboot, raw-запись и смена HOME не выполняются. При несовпадении подписи найдите исходный ключ, не удаляйте приложение.

После установки проверьте изменённую функцию, избранное, тему, VPN и веб-пульт. Для новых web assets обновите страницу браузера. Владелец может параллельно пользоваться пультом.

## Root и прошивка

Инструменты boot/AVB/Magisk находятся в отдельном **projector-root**. Их нет в build/install/check этого репозитория. Независимое восстановление не подтверждено; ограничения [AGENTS.md](../AGENTS.md) действуют и при наличии factory root.
