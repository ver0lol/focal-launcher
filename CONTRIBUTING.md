# Изменения проекта

Сначала прочитайте [AGENTS.md](AGENTS.md) и [текущее состояние](docs/CURRENT-STATE.md). Работайте из корня репозитория. Исходный код можно менять и проверять без подключённого проектора.

```sh
git switch -c feature/short-name
make check
make build
git diff --check
git diff
```

Для изменения веб-пульта редактируются `launcher/assets/remote/` и при необходимости Java API. Страница встроена в APK: одной правки файлов на компьютере недостаточно для изменения работающего устройства. После обычной установки APK обновите страницу браузера.

Для выпуска измените `versionCode` и `versionName` в `launcher/AndroidManifest.xml`. Сохраните совместимость настроек: `rice`, `web-remote` и `boot-home`. Миграции должны быть однократными, сохранять выбор владельца и не сбрасывать аккаунты других приложений.

Проверяйте поведение, которого касается изменение. Для небольшого изменения цвета/подписи достаточно сборки и целевой проверки; не добавляйте тест, который лишь повторяет реализацию. Для управления вводом, очередью, доступом или миграций нужны проверки реальных контрактов и ошибок.

`make install` — отдельное действие на живом устройстве, только в рамках запроса владельца. Оно не должно быть зависимостью сборки или проверки. Прошивка и reboot остаются запрещёнными согласно AGENTS.md.

Перед коммитом:

```sh
make check
git diff --check
git status --short
git add launcher docs AGENTS.md CONTRIBUTING.md Makefile scripts config .gitignore THIRD_PARTY.md README.md
git diff --cached --stat
git commit -m "Describe the resulting behavior"
```

Добавляйте только нужные существующие пути из примера. Не добавляйте APK, SDK, локальные профили, ключи или резервные копии. Не используйте `git add -f`. В описании коммита укажите результат и существенную проверку.

Откат установленной версии не требует удаления приложения: можно вернуть исходники нужного коммита, повысить versionCode и пересобрать тем же ключом. Это сохраняет избранное, тему и подключённые телефоны. Не выполняйте очистку данных для исправления сборки.

На Arch Linux полный цикл после изменения: `./focal update` (проверки, сборка, обычное обновление). Один раз импортируйте приватный комплект по [ARCH-LINUX.md](docs/ARCH-LINUX.md). Публикация исходников не разрешает запуск обновления устройства.
